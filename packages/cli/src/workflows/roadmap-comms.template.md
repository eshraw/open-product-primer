---
name: oprim-roadmap-comms
description: Draft audience-specific roadmap communication (now / next / later) from the boards and objectives into outputs/ — drafts only, never sends
---

Draft a roadmap communication — what we're doing now, next and later, and why — for one audience and one period, from the portfolio's and products' boards and the objectives they serve. The result is a **draft** in `outputs/` for the PM to edit and send themselves.

**Interactive prompts:** Use the **AskUserQuestion tool** for every question in this skill — do not write questions as plain text.

## Hard rules — never break these
- **Never send, post, email, publish or upload anything** — no chat, email, Notion or other external tool calls, even if such tools are available. The only file written is the draft under `outputs/`.
- Every claim about a bet cites its qualified reference: `<source>:BET-NNN` for a product bet, and `<portfolio>:BET-NNN` for a portfolio bet, where `<portfolio>` is this workspace's identity `name` from `.oprim-context/context.yaml` (fall back to the plain `BET-NNN` only if that file is missing). The same for objectives and PDRs.
- The roadmap reflects the boards as they are. Never re-order bets, invent dates, or move a bet between lanes in the draft; if the board looks wrong, say so in the report and suggest `/oprim:prioritize`.
- Never write `later`/`backlog` bets as commitments — label them "exploring".

## Steps

### 1. Check this is a portfolio workspace
Read `oprim/config.yaml`. If `mode:` is not `portfolio`, stop: "Roadmap comms run from a portfolio workspace (`oprim init --mode portfolio`)."

### 2. Ask audience and period
Ask, in one AskUserQuestion call:
- **Audience** — `exec`, `eng`, `sales`, `customers` (or another the user types). Use it as a lowercase slug in the filename.
- **Period** — the horizon the roadmap covers: a quarter (`2027-Q1`), a month (`2027-01`) or a date range. Default: the current quarter.

<!-- oprim:portfolio:start -->
### 2b. Ask about assumptions first
Before drafting, ask 2–3 questions about what this audience needs from the roadmap — the decision it should support, what they were last told, and anything that must stay internal — and wait for the answers. Shape the draft around them, and list anything left unanswered under `## Open questions` at the end of the draft. (`rules.roadmap-comms.ask_first: false` in `oprim/config.yaml` turns this step off.)
<!-- oprim:portfolio:end -->

### 3. Gather inputs (read-only)
- `oprim ovw --portfolio --json` — every board's `now`/`next`, cross-product dependencies, delegations, objective coverage.
- The portfolio's `oprim/sequence.yaml` `later`/`backlog` lanes, and each product's via `oprim context --source <product>`.
- `oprim/objectives/OBJ-*.md` — which Active objective each bet serves (from its `## Links`).
- Bet decisions for each bet mentioned (`## Why now`, `## Expected outcomes`, `## Door type`).
- `rules.roadmap-comms` in `oprim/config.yaml`: if it is a string, or a map with a `text` key, apply that text as additional guidance.

### 4. Write the draft
Write `outputs/<YYYY-MM-DD>-roadmap-comms-<audience>.md`, where the date is the **last day of the period** (period `2027-Q1` → `2027-03-31`; for an open-ended period, today). Create `outputs/` if needed. If the file exists, ask before overwriting. Layout:

```
> DRAFT — verify before sending. Generated by /oprim:roadmap-comms from git on <today>; every bet is cited so it can be checked.

# Roadmap — <period> (<audience>)

## Why — objectives
<each Active objective in one line>

## Now
<bets in Now, grouped by objective, one line of why each, with refs>

## Next
<bets in Next, with refs>

## Exploring
<later/backlog bets worth mentioning — explicitly not commitments>

## Dependencies and risks
<cross-product blockers and 1-way-door bets, with refs>
```

Tune to the audience: **exec** — objectives and trade-offs; **eng** — dependencies and sequencing across products; **sales** — capabilities and only the dates written in a bet; **customers** — benefits only, no internal IDs in the prose (keep refs in a final `## Sources` list), no `Exploring` items unless the PM says so.

### 5. Report
Give the file path, the refs it cites, any board oddities you noticed (with a pointer to `/oprim:prioritize`), and any `[TBD …]` placeholders.
