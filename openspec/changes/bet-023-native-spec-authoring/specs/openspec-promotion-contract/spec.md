## MODIFIED Requirements

### Requirement: Bet promotion SHALL create explicit linkage to OpenSpec changes
The system SHALL define a promotion contract where prioritized bets are linked to the artifact generated by the project's selected speccing framework — an OpenSpec change directory when `integrations.spec_framework` is `openspec`, or a native oprim spec file when it is `native` — without duplicating implementation details in primer artifacts, and where notes promoted into a bet are linked to that bet. When the selected framework is `none`, promotion links the bet to no generated spec artifact.

#### Scenario: Promote a bet into an OpenSpec change
- **WHEN** a user promotes `BET-XXX` for implementation and the project's selected speccing framework is `openspec`
- **THEN** the bet artifact links to the created OpenSpec change path and OpenSpec artifacts reference the originating bet ID

#### Scenario: Promote a bet into a native oprim spec
- **WHEN** a user promotes `BET-XXX` for implementation and the project's selected speccing framework is `native`
- **THEN** `promoteContent()` invokes the native spec-authoring skill instead of `/opsx:propose`, the bet artifact links to the resulting `oprim/specs/<capability>/spec.md` path, and no OpenSpec change directory is created

#### Scenario: Promote a bet with no speccing framework selected
- **WHEN** a user promotes `BET-XXX` for implementation and the project's selected speccing framework is `none`
- **THEN** promotion completes without creating any spec artifact, and the bet decision records that no spec framework is in use

#### Scenario: Promote a note into a bet
- **WHEN** a user runs `/oprim:promote NOTE-XXX`
- **THEN** a new `BET-NNN` bet is created with `bet-decision.md`'s `Why now` pre-filled from the note's body, the note links to the resulting bet ID, and the bet is registered in `oprim/sequence.yaml`
